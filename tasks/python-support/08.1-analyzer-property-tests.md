# Task 08.1: Add analyzer property tests

**Phase:** Validation and release  
**Priority:** MVP  
**Estimate:** 1 day  
**Depends on:** Tasks 05, 07  
**Source:** plan review §9 (test properties of the analyzer, not only individual imports)  
**Status:** Done. The deliberate breaks are listed in the release review section of the decision record

## Goal

Check properties that individual fixtures cannot: results do not depend on input order, discovery never runs project code, and cached results match clean results.

## Work

- **Determinism:** run Python resolution with module and root lists in several shuffled orders and require identical resolved imports, unresolved lists, and graph edges.
- **No execution:** run discovery and `scanGuard` on a Python fixture whose `setup.py`, `noxfile.py`, `conftest.py`, and package `__init__.py` would write a marker file if executed. Mock `node:child_process` and require that only `git` is invoked and the marker never appears.
- **Cache consistency for Python:** apply a sequence of edits (`services.py` replaced by `services/__init__.py`, a new `pyproject.toml` that adds a resolution root, an `__init__.py` removed) and require that discovery with the persisted cache matches discovery after `clearDiscoveryCache` at each step.
- **Language isolation:** extend the Task 02 tests so a Python import never resolves to a JS/TS file.

## Acceptance criteria

- All four property groups run in the unit test suite without installing or executing Python.
- Each property test fails when the property is broken on purpose (for example, by removing the sort of resolution roots), which is checked once while writing the test.
