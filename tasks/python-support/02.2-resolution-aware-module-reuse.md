# Task 02.2: Make module reuse depend on resolution inputs

**Phase:** Architecture  
**Priority:** MVP, fixes an existing JS/TS bug  
**Estimate:** 1 day  
**Depends on:** Task 02  
**Source:** plan review §6 (parse facts and resolution results have different lifetimes), decision D18  
**Status:** Done. The fingerprint also covers lockfiles, `tsconfig*.json` bases, and `.json` and `config`/`schema` file paths, and the unresolved status is recomputed on every discovery; details and the benchmark are in D18 and D13

## Goal

Stop reusing cached module records whose import resolution is stale.

Discovery reuses a cached module when its content hash is unchanged, the source/test file list is unchanged, and `git diff HEAD` shows no `tsconfig.json`/`jsconfig.json` change (`resolutionConfigChanged` in `discoverProjectOnce`). A committed config change, or any change in a project without git, is invisible to that check. Reproduced on v0.9.0 plus Tasks 01–02: after retargeting a tsconfig path alias from `a/` to `b/` and committing, a fresh process still resolves `entry.ts` to `a/lib.ts`.

## Work

- Compute a resolution-input fingerprint from the content of every `tsconfig.json`, `jsconfig.json`, and `package.json` in the project, plus the sorted source/test file list that the current shape check already builds. Store it in the persisted cache next to the model.
- Reuse module records only when the stored fingerprint equals the current one. Remove the `git diff`-based `resolutionConfigChanged` check.
- JS/TS resolution comes from `ts-morph` during parsing, so JS/TS reuse stays all-or-nothing on the fingerprint. Python resolution (Task 05) runs as a separate pass over cached parse facts on every discovery, so it does not need this fingerprint.
- Bump `DISCOVERY_CACHE_VERSION` if the cache format changes.

## Acceptance criteria

- A regression test reproduces the committed tsconfig case above and gets the new target.
- A test covers the same change in a project without git.
- A cache-consistency test applies a sequence of edits (alias retarget, `package.json` exports change, file added, file removed) and checks that discovery with the persisted cache returns the same modules and edges as discovery after `clearDiscoveryCache`.
- The warm benchmark stays within 5% of the Task 02 build (D13 method).
