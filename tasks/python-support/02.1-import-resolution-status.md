# Task 02.1: Record import resolution status

**Phase:** Architecture  
**Priority:** MVP, blocker for Tasks 05 and 07.1  
**Estimate:** 1–2 days  
**Depends on:** Task 02  
**Source:** plan review §2 (resolved, external, and unresolved must not be mixed), decision D16  
**Status:** Done. The fixture review found and fixed a directory-require resolver bug; results and the fingerprint effect are in D16

## Goal

Distinguish imports that point to local code but did not resolve from imports of external packages. Today both look the same in the model: a spelling with no entry in `resolvedImportMap`. A missing local edge is a gap in the graph, while an external package is expected, and later tasks need to tell them apart.

## Work

- Add an optional `unresolvedImports?: string[]` field to `ModuleRecord`: spellings that look local by the language's static rules but did not resolve to a project file.
- Add an exported helper in `src/core/discovery/discovery.ts`, for example `importResolutionStatus(module, spelling): 'resolved' | 'unresolved' | 'external'`, so consumers never reimplement the classification. `resolved` means present in `resolvedImportMap`, `unresolved` means listed in `unresolvedImports`, and everything else is `external`.
- Keep the existing parallel fields. Do not replace `ModuleRecord` imports with a separate import-record entity, because policy, packs, budgets, MCP output, and persisted state all read the current fields.
- JS/TS rules for "looks local":
  - relative (`./`, `../`) and absolute (`/`) specifiers;
  - specifiers matching a `tsconfig.json`/`jsconfig.json` path alias pattern;
  - specifiers naming a workspace package, either the bare name or `name/subpath`.
- A relative specifier that points to an existing non-source project file (for example `./styles.css` or `./data.json`) is not unresolved.
- Python rules, implemented in Task 05: relative imports, and absolute imports whose first segment names a top-level package or module in a resolution root.
- `external` means "not resolved locally and not classified as local by static rules". It does not claim the package is installed or exists.
- Bump `DISCOVERY_CACHE_VERSION`.

## Acceptance criteria

- Unit tests cover a relative import of a missing file, an alias that matches no file, a bare package, a relative import of an existing asset, and a workspace package import, each with the expected status.
- On the five external fixtures, every `unresolved` entry is reviewed and is either a real gap (for example a workspace package that resolves only after install) or a classification bug that gets fixed. The counts are recorded in D16.
- JS/TS findings, resolved imports, and dependency edges on the fixtures are unchanged.
