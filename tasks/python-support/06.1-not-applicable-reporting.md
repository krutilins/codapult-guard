# Task 06.1: Report checks that could not be evaluated

**Phase:** Policy integration  
**Priority:** MVP  
**Estimate:** 1–2 days  
**Depends on:** Task 04  
**Status:** Done. Implementation details and the Flask counts are in D17
**Source:** plan review §4 (pass and not-applicable must be distinguishable) and §12 (decide applicability from facts, not language names), decision D17

## Goal

Make skipped checks visible. Under D8, `required-call`, `package-boundary`, and `client-forbidden-import` skip Python modules. Without reporting, a CI run stays green and users cannot tell whether a contract passed or was never evaluated.

## Work

- Define in discovery which facts each language collects, as one table: JS/TS collects `imports`, `calls`, `directives`, and `packages`; Python collects `imports`. Expose it as a helper such as `collectedFacts(path)`.
- Give each rule and contract kind the facts it requires: `client-forbidden-import` needs `directives`, `required-call` needs `calls`, `package-boundary` needs `packages`, and the other kinds need `imports`. Policy code checks facts, never language names.
- When a module in scope lacks a required fact, skip it for that check and record it. Add `notApplicable: { ruleId: string; reason: string; modules: number }[]` to `GuardReport`, aggregated per rule and reason.
- Show the entries in CLI output as a short summary, return them in MCP results, and write them to SARIF as `invocations[0].toolExecutionNotifications` with level `note`.
- Not-applicable entries never change the exit code or `classifyGuardOutcome`. Document this.
- Replace the interim `required-call` skip from Task 04 (`module.pythonImports === undefined` in `scanContracts`), which skips Python modules without reporting them.

## Acceptance criteria

- A `required-call` contract scoped to a mixed directory reports findings for JS/TS modules only and one `notApplicable` entry with the Python module count.
- Equivalent tests cover `package-boundary` and `client-forbidden-import`.
- A JS/TS-only project produces an empty `notApplicable` list, so existing CLI output and SARIF are unchanged.
- The SARIF output with notifications passes the existing SARIF tests.
