# Task 07.1: Report graph completeness

**Phase:** Shared analysis integration  
**Priority:** MVP  
**Estimate:** 1 day  
**Depends on:** Tasks 02.1, 05  
**Source:** plan review §5 (an incomplete graph silently weakens impact analysis) and §8 (users must see when files were not fully analyzed)  
**Status:** Done. Fixture and Flask values are in D16

## Goal

Tell users when the graph has gaps. If `services.py` imports `database.py` and that import does not resolve, a change to `database.py` shows no effect on `api.py`. The algorithm is correct, but the result is incomplete.

## Work

- Add an import-resolution summary to the model insights, per language: module count, resolved, unresolved, and external import counts (from Task 02.1), and the number of modules with `parseDiagnostics` (D3).
- Add a graph status to `analyzeProjectImpact` results: `complete` when no affected module has unresolved imports, otherwise `partial` with a bounded list of the unresolved imports in affected modules.
- Show the summary in `doctor` and in CLI and MCP impact output.
- Wording in output and docs: "complete within the supported static subset". Dynamic imports are never counted, so `complete` is not a runtime guarantee.

## Acceptance criteria

- Tests cover a complete Python chain, a chain broken by an unresolved relative import (status `partial` with that import listed), and a module with parse diagnostics.
- External imports never make the status `partial`.
- JS/TS projects show the summary as well. The values for the five fixtures are recorded in D16.
